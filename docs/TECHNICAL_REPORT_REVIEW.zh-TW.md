# 技術分析報告 — 審查清單

*[English](TECHNICAL_REPORT_REVIEW.md) · 繁體中文*

**目的：** 列出影響 `technical-analysis` 報告的每個環節，從抓取的 OHLCV 到發佈的頁面，讓每一部分都能獨立審查。本文是 `FUNDAMENTAL_REPORT_REVIEW.zh-TW.md`（[PR #82](https://github.com/yennanliu/finance_data/pull/82)）的姊妹篇，結構相同。

**範例：**
[`/reports/amzn/technical_analysis_2026-10-23_gemini/`](https://yennj12.js.org/finance_data/reports/amzn/technical_analysis_2026-10-23_gemini/)（由殘缺的 context 生成，見 §1.1）與
[`/reports/avav/technical_analysis_2026-10-22_gemini/`](https://yennj12.js.org/finance_data/reports/avav/technical_analysis_2026-10-22_gemini/)（正常情況）。

**事實查核：** `ai_gen_report/technical/` 下**全部 27 檔**的最新技術報告，以各報告 commit 時點的 Yahoo 日線 OHLCV 為準逐一核對；另對 10 月提交的全部 550 份技術報告做價格新鮮度掃描。見 [§7](#7)。

**重點：** context 完整時，模型照抄得很忠實。在 context 正常的報告中，所有指標以及 90 個支撐/阻力位中的 88 個都與 context 分毫不差，另外 2 個分別標明為 52 週低點與斐波那契位。嚴重問題都在上游：
- **最後一根 K 棒為空（8/27）：** 空的最後一根日 K 讓 27 份中的 8 份 context 被悄悄清空，模型仍在沒有數據的情況下寫完整份報告，包括自創的支撐/阻力位。10 月 550 份報告中有 79 份用的是前一交易日收盤價。
- **0050 全數捏造（21/21）：** 0050 在 10 月每天都是完全捏造的，價格高出約 80%。
- **非標準 RSI：** 管線的「RSI(14)」不是任何看盤網站顯示的 RSI。它把 24 檔中的 7 檔算在 30 以下（超賣），標準（Wilder）RSI 則落在中性區間。

## 1. 資料抓取與指標計算

檔案：`data/sources.py`、`data/technicals.py`。

### 1.1 最後一根 K 棒為空，整個 context 被清空 — **嚴重**

`fetch_data` 原樣回傳 Yahoo 日線歷史，`compute_technicals` 讀取 `close.iloc[-1]`。美股收盤後，Yahoo 常會先發佈新交易日的 K 棒，**有成交量但開高低收皆為 NaN**，持續約一到兩小時；2026-10-23 在 00:14–01:05 UTC 之間提交的每一份都受影響。結果：

- `收盤價` 與 `當前價格` 顯示為 `$nan`。
- 所有滾動指標（MA5–MA240、RSI、ATR、布林、KD）皆為 `N/A`。
- `compute_levels` 拿價位跟 `nan` 比較，所以**完全不輸出 R1–R3 / S1–S3**。
- 只有 EWM 類的值留下來：MACD、ADX/±DI，以及量比（用的是*新*交易日的成交量配上前一日的價格）。

已完整重現：以空的 10-22 K 棒重建 AMZN 的 context，得到 MACD 1.643 / 0.863 / +0.780、ADX 14.32、+DI 21.94 / −DI 15.75、量比 1.34x，正是已發佈報告引用的數值；其餘指標皆為 `N/A`。

模型不會停下來，照樣寫完 9 章：
- **價格：** 從週線表取值，也就是前一日收盤價。
- **價位：** 用斐波那契點位與週收盤價拼出支撐/阻力。
- **指標：** 自行估算 RSI、MA、ATR（§7.3）。

`last_completed_close()`（PR #84）與 `quote_close()`（PR #85）只修正了**基本面** context（`_market_overview`）的標題價格。`compute_technicals` 仍讀取原始 `hist`，所以 **`main` 上尚未修正**。

**檢查／修正：**
- 計算任何指標前，先去除 `Close` 為 NaN 的尾端 K 棒（`hist = hist[hist["Close"].notna()]`）。
- 再以 `quote_close()` 補上官方收盤價，否則跳過本次執行。
- 快照價格為 NaN 時拒絕生成。以 `$nan` 為基礎的報告應該是失敗的執行，而不是發佈的頁面。

### 1.2 0050 完全沒有資料 — #84 已修，技術報告尚待驗證

0050 技術報告在 10 月每天都是以空的歷史資料生成。Yahoo 上單純的 `0050` 會回 404，#84 起改為請求 `0050.TW`。模型自行補上空缺；10-23 的報告在標題直說了（「鑑於即時資料包缺失歷史報價，本報告依據…技術建模推演完整 OHLCV 基準數值」），接著發佈價格 $192.50、MA200 $165.80、RSI 58.20 與六個支撐/阻力位。實際收盤價是 NT$108.15。**10 月全部 21 份 0050 報告**的價格都在 $192.5–$198.5 之間（§7.4）。

**檢查：** 確認 #84 之後第一份 0050 技術報告的價格約為 NT$106–108。另外，沒有 OHLCV 的 context 應中止執行（與 §1.1 相同的防護）。

### 1.3「RSI(14)」不是 Wilder RSI

`compute_technicals` 以 **14 日簡單平均**（`rolling(14).mean()`）計算漲跌幅平均，即 Cutler RSI。所有看盤網站、以及任何拿報告去對照的讀者，用的都是 **Wilder 平滑**（α = 1/14 的 EMA）。在歷史資料足夠的 24 檔中：

| | 檔數 |
|---|---|
| \|SMA-RSI − Wilder RSI\| ≥ 5 點 | 14 / 24 |
| ≥ 10 點 | 4 / 24（INTC 14.5 vs 36.4、RKLB 16.0 vs 30.2、TSM 26.1 vs 38.0、NU 65.7 vs 54.3） |
| SMA-RSI 超賣（<30）、Wilder 為中性 | **7**：INTC、RKLB、TSM、MRVL、PL、ONDS、NBIS |

報告接著把這些稱為「超賣」，並據此制定策略章節。ATR 同樣用真實波幅的 SMA，但差距小（≤ 10%，VST 例外：9.41 vs 7.43）。ADX 已使用 Wilder 平滑。

**修正：** RSI 與 ATR 改用 `ewm(alpha=1/14, adjust=False)`；或在 context 中明確標示為 Cutler/SMA，避免報告把它當成標準值。

### 1.4 週線表以未來日期標示

`close.resample("W")` 以**週日**標示每一週，因此 10-23 生成的報告中，進行中的那一週標為 2026-10-25；27 份最新報告中有 21 份引用了這個日期（例如 PL：「依據…2026-10-25 週線收盤價精確錨定」）。最後一根 K 棒為空時，「10-25」那列其實是 10-21 的收盤價。

**修正：** 以該週最後一個交易日標示（`groupby(pd.Grouper(freq="W"))` → `index.max()`），或改用 `resample("W-FRI")`。

### 1.5 context 沒有開高低，prompt 卻要求 K 線形態

context 只有收盤價：月收盤、20 週收盤，以及 52 週高低點。第 3 章仍要求「重要K線形態」，而 27 份報告全都描述了無法由這些數據推得的 K 線或影線（錘頭、十字星、吞噬、上/下影線）。

例：SPCX 把標為 10-18 的那一週稱為「探底回升槌頭線 (Hammer)…留下明顯下影線」。實際週 K 為 開 164.66 / 高 167.07 / 低 140.66 / 收 146.03，是收在低點附近的長黑實體，而且收盤價*低於*同一列聲稱「確認有效守住」的 S1 $146.24。

**修正：** 在 context 加入最近約 10 根日 K 與約 8 根週 K 的開高低收，或從 prompt 移除 K 線表。

### 1.6 RSI 背離只比較兩個點

`divergence` 只比較 20 根 K 棒中第一根與最後一根的價格和 RSI，標示的是這段期間的方向，而非以轉折點判斷的背離。prompt（規則 7）要求模型「明確判斷」背離，卻只提供這個旗標。優先度低，但 context 應如實描述（例如「20 根 K 棒方向比較」）。

### 1.7 除息還原造成歷史價格漂移

yfinance 歷史價格在每次除息日都會向前還原，因此舊報告的價格與今天的序列對不上。例如 ORCL 10-01…10-09 的報告比還原後收盤價高約 0.4%。這不是報告錯誤，但任何複核都必須使用未還原收盤價（`auto_adjust=False`）或價格資料庫。

## 4. 策略算術 — 可由程式檢查

我們從第 8 章解析出 44 組進場／止損／目標價計畫：

| 檢查 | 結果 |
|---|---|
| 所述 R/R 能由進場、止損與其中一個目標價複算 | 43 / 44。**TSM** 策略 A 寫 1 : 3.48，但同一格自己寫的「風險 $11.5，目標2獲利 $51.97」算出來是 1 : 4.52 |
| R/R 用的是哪個目標價 | 不一致：約一半用 T1，一半用 T2，且很少註明（PLTR 的「以 T2 計算」是例外）。以 T2 計算會讓計畫看起來約好兩倍 |
| 以 T1 計算 R/R < 1 卻被推薦的計畫 | NU 策略 B（0.46，所述亦為 0.46）。SPCX 策略 B（T1 為 0.56，所述 0.99 是以 T2 計算） |
| 情境機率加總為 100% | ✅ 有此表的 26 / 26（MRVL 的 7 月報告早於此表） |

**修正：** 在 prompt 中定義 R/R 為 `(T1 − 進場) / (進場 − 止損)`，做空時方向相反；再加上生成後的檢查，比照 `validate/arithmetic.py` 對 §8.8 的做法。

## 5. QA 關卡 — 涵蓋範圍

第一階段（`validate/__init__.py`）**沒有任何技術報告專屬檢查**。本文的每一項缺陷都通過了 QA，27 份報告全數發佈。可加入的低成本、確定性檢查：

1. **生成前：** 最後收盤價為 NaN 或缺漏、或 `hist` 為空時，執行應失敗（§1.1、§1.2）。
2. 報告中出現 `$nan` 或 `nan%` → 標記。
3. 標題「當前價格」應與 context 的收盤價一致。
4. 第 4 章表格中每個 R1–R3 / S1–S3 應與 context 中同標籤的計算價位一致（§7 的解析器已能做到）。
5. 所述 R/R 應能複算（§4）。

第二階段（LLM 審查）抓不到 §1.1–§1.4：評審從未看到 context 或市場數據。

## 7. 事實查核：每檔最新技術報告

**方法：**
- **數據：** Yahoo 日線 OHLCV（`period=3y`），截取到每份報告 **git commit 時點**已收盤的交易日。
- **Context：** 以 repo 自己的 `compute_technicals` 重建三種候選 context：*正常*、*最後一根 K 棒為空*（開高低收為 NaN、保留成交量）、*落後一個交易日*。每份報告對應到與其共有最多小數數字的候選。
- **檢查項目：**
  - 報告引用的指標與支撐/阻力位 vs 該 context
  - 標題價格 vs 實際最後收盤價
  - R/R 算術與機率加總
- 檢查用的腳本未納入 commit。

### 7.5 查核結論

1. **prompt 的數據紀律有效。** context 有數字時，報告照抄無誤：指標 18/18、價位 88/90。準確度的問題不在 prompt 調校。
2. **管線會發佈沒有數據支撐的報告。** NaN 的最後一根 K 棒、或 0050 的 404，產出的是一份自信滿滿的 600 行報告，而不是一次失敗的執行。這是最主要的修正點。
3. **有一個指標標示錯誤。** 「RSI(14)」的算法是讀者無法重現的，在 7 檔中翻轉了超賣判斷。
4. **context 承諾的比它提供的多：** 沒有開高低卻要求 K 線形態，週線還標上未來日期。
